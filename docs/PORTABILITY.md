# Контракт для ChatGPT, Gemini, DeepSeek, Claude — V1.1

## Что одинаково

Одна инструкция `SKILL.md`, одна карта `case_schema.json`, один Python-исполнитель и два неизменных бинарных шаблона. Название модели не меняет алгоритм заполнения. При одинаковых нормализованных реквизитах, версии кода/шаблонов и совместимой среде результат формирования DOCX повторяем. Тест сравнивает SHA-256 четырех запусков с разными метками происхождения данных; это **не четыре вызова LLM**.

Чтение скана и интерпретация источника разными моделями могут различаться. Никакой Markdown не гарантирует одинаковое извлечение на всех LLM. Поэтому цитаты-основания, блокировка неоднозначных дат и проверка сотрудником остаются обязательными.

## Минимальные возможности любого чата

1. Получить полный текст инструкции, карты/кода и реальные байты обоих DOCX. Извлеченный из Word текст недостаточен.
2. Прочитать текущие материалы клиента и выполнить доверенный Python-код со стандартной библиотекой в среде с доступом к рабочим файлам.
3. Отдать два реально созданных DOCX штатными вложениями/ссылками своей платформы.

Не требуется терминал у сотрудника, API-ключ или установка Skill в системный каталог. Если платформа не дает этих возможностей, это техническая несовместимость конкретной среды; модель не должна сочинять новый шаблон или поддельную ссылку. Сначала попробуй доступные файлы/разрешенные инструменты. Если исходники недоступны, сообщи отказ без опросника.

## Настройка адаптера

- ChatGPT: разрешенные инструменты чтения источников, исполнения Python и создания вложений. Использовать реальные пути и только поддерживаемые этой средой ссылки.
- Gemini: та же инструкция; требуется выполнение **предоставленного** исполнителя над исходными DOCX, не свободное создание нового документа/экспорт через другой редактор.
- DeepSeek: та же инструкция. Наличие API/текстового ответа само по себе не доказывает доступ к файловому исполнителю. При отсутствии такого инструмента контракт не исполнен.
- Claude: та же инструкция; использовать файловую вычислительную среду и исходные шаблоны, не пересобирать документ в Artifacts по своему стилю.

Эти строки — требования адаптации, а не сертификат доступности функций в каждом аккаунте или тарифе. Доступность проверяется в конкретном чате. Живые сессии ChatGPT/Gemini/DeepSeek/Claude в рамках этой поставки не испытывались.

## Единый приемочный пример

Синтетический акт: «Рассмотрев гражданское дело ... 10.06.2026 г. Дата вступления судебного акта в законную силу: 24.07.2026». Внутренняя карта: `decision_date=2026-06-10`, `legal_force_date=2026-07-24`. Отдельно переданная `awareness_date` не заполняет ручные места.

Проверить наличие двух DOCX; дату решения во всех соответствующих местах; отсутствие даты вступления в силу вместо решения; точные ручные фрагменты из SKILL; свойства курсива/подчеркивания; сохранение остальной верстки. Для проверки живого провайдера отдельно записать модель, дату, доступные инструменты, факт чтения оригиналов, SHA-256 исходников и получившихся файлов; не публиковать персональные данные. Совпадение хешей ожидается только для одинаковых реквизитов и того же исполнителя, не для произвольных новых сочинений моделей.
