# Приемка V1.1 — 22.09.2026

## Изменения

Дата решения отделена от даты вступления в силу. Добавлена консервативная проверка числовых дат по явным меткам исходного текста. Ручные даты уведомления заблокированы для автозаполнения; точные фрагменты и прямые свойства Word italic/underline проверяются перед записью. Поддержана корректная метка БИН/ИИН. Ведущий знак № нормализуется без потери суффикса номера дела.

## Локальные результаты

**54/54 теста пройдены:** 32 регрессионных с двумя согласованными обновлениями ожиданий (статус ручного заполнения и БИН) плюс 22 новых контрактных проверки. Проверены оба результата, пропуски/конфликты, запрет подмены дат, сохранение формата, защита оригиналов, повторные реквизиты и CLI из другого рабочего каталога.

Четыре запуска одного исполнителя с одинаковыми данными и разными метками происхождения ChatGPT/Gemini/DeepSeek/Claude дали одинаковые SHA-256 DOCX. Это симуляция входов для проверки повторяемости кода, **не испытание живых моделей**.

Созданы два DOCX по синтетическому примеру: решение 10.06.2026, вступление в силу 24.07.2026, отдельная переданная дата уведомления. В Word подставлена дата решения; уведомление осталось ручным. Дата вступления в силу записана только в локальном отчете. Статус: `FILLED_REQUIRES_MANUAL_COMPLETION`.

## Оригиналы и верстка

Оба исходных DOCX сохранены побайтно; SHA-256 не изменены:

- заявление: `0fd6b78c72c8c123b418bd191e3b1cbbfdc33b48e01fbc12a84813e0c43272a6`;
- ходатайство: `5ec8add42dc52eab9e0319764efb481fcd84a6d922ca3541a86731cc6960e91d`.

Результаты отрендерены; просмотрены все четыре страницы (по две на документ). Ручные фрагменты видны с курсивом и подчеркиванием, исходное желтое выделение сохранено, наложений/обрезки текста не обнаружено. В ходатайстве сохранились известные особенности эталона: разрыв ФИО ответчика из-за 93 ведущих пробелов и заголовок «ПРОШУ СУД» на странице перед пунктами. Эти особенности не исправлялись, поскольку новая задача не разрешала перестройку верстки. Совпадение переносов при любой длине реквизитов не гарантируется.

## Что не подтверждено

Живой сценарий «ссылка + PDF» во всех четырех сервисах не выполнялся. Произвольные сканы/PDF, почерк, OCR и все формы судебных актов этим тестированием не покрыты. Дата-парсер консервативен и при нескольких датах блокирует неоднозначное поле. Актуальность правовых абзацев V1.1 не удостоверяет; требуется проверка сотрудником перед подачей.

Текущий результат GitHub Actions нужно смотреть по конкретному опубликованному commit; этот файл фиксирует локальную приемку до публикации. Автоматическая CI имеет только `contents: read`, не публикует клиентские артефакты и не вызывает внешние LLM.
