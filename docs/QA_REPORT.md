# Техническая проверка V1

Дата: 22.09.2026.

## Подтверждено выполненными проверками

- Тесты исполнителя: **32/32 PASS** (`python -m unittest discover -s tests`).
- В карте: **39 адресных областей замены** в двух документах; отдельное условное правило приложений не входит в это число.
- Оригиналы скопированы побайтно; их SHA-256 совпадают с пользовательскими исходниками.
- При полных синтетических данных исполнитель создал ровно **2 DOCX**. При неполных данных — также два DOCX с префиксом `ЧЕРНОВИК_`.
- Во всех неизменяемых частях заполненного DOCX байты совпадают с исходником. Реквизиты не меняют свойства абзацев, runs, таблиц, полей страницы, шрифтов, выделений и нумерации. Условное исключение: отключение номера пустого пункта приложений при явном отсутствии доказательств.
- Проверены повторные номера дела, ведущие нули ИИН, казахские буквы, XML-экранирование, неподтвержденные факты, несовместимый тип акта, отсутствие источника, неполные/конфликтующие поля, неверные даты, исходные «2025»/«Алматы», контроль хеша и запрет смешивать выходы разных клиентов.
- Просмотрены **8 изображений страниц**: по две страницы каждого оригинала и по две страницы каждого заполненного синтетического примера.

## Ограничение внешнего вида — обнаружено, не скрыто

Оба исходника и оба тестовых результата в примененном рендерере занимают по две страницы. Обрезки и наложения текста на просмотренных страницах не обнаружены. Однако переносы после подстановки изменились:

1. В шапке ходатайства ФИО `Тестов Тест Тестович` перенеслось на две строки. Причина связана с исходными 93 пробелами перед полем и его форматированием. Это выравнивание не исправлялось, поскольку пользователь потребовал сохранять эталон.
2. В ходатайстве первый пункт просительной части переместился со страницы 1 на страницу 2.
3. В заявлении абзац о представлении доказательств переместился со страницы 1 на страницу 2.

Поэтому **попиксельное совпадение страницы после заполнения не подтверждено**. Подтверждено сохранение свойств исходного DOCX и точечная подстановка. Автоматическое уменьшение шрифта, сокращение реквизитов, удаление исходных пробелов или изменение полей не выполнялись.

Рендеринг выполнялся LibreOffice. В среде шрифт Times New Roman сопоставлялся с Tinos; просмотр в Microsoft Word не выполнялся. Сравнение исходников и результатов проводилось в одинаковой среде. Файлы шрифтов не включены в поставку.

## Что не проверялось

- Сквозная работа «обычный чат конкретного сотрудника → только GitHub-ссылка → скачивание полных DOCX → два файла». Репозиторий этой поставкой не изменялся; испытание опубликованной ссылки не проводилось.
- Автоматическое извлечение реквизитов из реального судебного PDF. Сотруднический ввод обрабатывает GPT по `SKILL.md`; исполнитель принимает уже сформированный JSON. Юридических документов реального клиента для такого теста в текущей задаче не было.
- Качество распознавания сканированных судебных актов, различных печатей и рукописных реквизитов.
- Правильность склонения любых реальных названий/ФИО и суммы прописью. Их формирует GPT по указанным источникам; перед выдачей нужна сверка.
- Действующее законодательство, расчет процессуальных сроков, достаточность оснований, наличие уведомления по реальному делу и пригодность заявления к подаче. **32 технических теста не являются юридической экспертизой.**
- Автоматическая отправка документов в суд, CRM, GitHub или третьим лицам. Такие функции не реализованы.
