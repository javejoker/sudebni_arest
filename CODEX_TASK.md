## Задача после разрешения на размещение

Прочитать `README.md`, `SKILL.md`, `docs/TEMPLATE_REVIEW.md`, `docs/QA_REPORT.md`. Проверить фактическое состояние репозитория через авторизованное подключение. Не предполагать, что он остается пустым. Не искать и не импортировать материалы соседних проектов, CRM, архивов клиентов или пользовательские секреты.

Разместить файлы этой поставки без изменения обоих `templates/*.docx`. Перед записью сверить текущую ветку и отсутствие конфликтующих пользовательских файлов. Для непустого репозитория использовать отдельную ветку и PR; не перезаписывать `main` без разрешения. Для действительно пустого репозитория нет базы для PR: первоначальный commit/ветка создаются только в рамках полученного разрешения. Не использовать force push.

До публикации выполнить 32 теста и проверить SHA-256 из `manifest.json`. Не коммитить `out*`, `case.json`, `validation.json`, `.env`, кэши, реальные судебные документы и данные клиентов. В тестовом JSON сведения явно синтетические.

Не менять правовые тексты, адресную карту полей, формат вывода «два DOCX», правило «без вопросов» и запрет выдумывания. Не добавлять API, сервер, Work, CRM, внешнее хранение или автоматическую подачу документов.

## Приемка реального сценария

1. В обычном чате сотрудника дать ссылку на опубликованный `SKILL.md` и синтетические сведения (не код).
2. Установить, доступны ли этому чату полные исходные DOCX и создание файлов. Проверить фактический путь получения байтов; не подменять его обещанием, что Python сам скачает URL.
3. Получить два DOCX, проверить все повторные реквизиты и изображения всех страниц.
4. Проверить неполные данные: должны быть два черновика без уточняющего вопроса и без придуманной даты получения.
5. Проверить длинное ФИО в шапке ходатайства. V1 сохраняет 93 исходных пробела; в локальном примере был перенос ФИО. Не объявлять формат «один в один» до проверки на типичных реальных длинах.

Если потребуется исправление хрупкой шапки, оформить отдельную минимальную редакцию эталона с визуальным сравнением и получить разрешение владельца. Не заменять оригинал молча. Это не задача публикации текущей V1.
