# sudebni_arest — два DOCX по эталонам

**V1.0.0, 22.09.2026.** Заполнение двух конкретных пользовательских шаблонов без их пересоздания. Не универсальный генератор судебных обращений.

## Для сотрудника

Откройте обычный чат, приложите судебный документ или введите сведения о клиенте и дайте ссылку на `SKILL.md` с командой:

> Примени SKILL.md из этого репозитория к приложенным данным. Без уточняющих вопросов заполни оба исходных DOCX и приложи два файла. Отсутствующие сведения не выдумывай.

Ссылка для сотрудников:

```text
https://github.com/javejoker/sudebni_arest/blob/main/SKILL.md
```

Результат: заявление об отмене решения и ходатайство о восстановлении срока. При неполных данных — оба черновика и короткая отметка о пробелах, без диалога-опросника.

## Статус размещения

V1 опубликована в ветке `main`. `CODEX_TASK.md` и `docs/QA_REPORT.md` сохранены как материалы этапа подготовки ZIP, до публикации; указанный в них статус `GITHUB_NOT_DEPLOYED` относится к тому этапу. Проверка опубликованного комплекта выполняется в GitHub Actions: `Verify package`. Сквозная проверка в обычном чате сотрудника остается отдельным этапом.

## Что внутри

| Файл | Назначение |
|---|---|
| `SKILL.md` | Главная инструкция для GPT |
| `templates/*.docx` | Оба оригинала, без изменения байтов |

| `CODEX_TASK.md` | Передача для размещения и пилота |

## Важно

Одна ссылка не устанавливает системный Skill и не гарантирует, что конкретный чат сможет скачать двоичные DOCX и создать файлы. Нужны доступ к инструкции, доступ к полным исходным DOCX и рабочая среда создания файлов. Обычный Python-инструмент ChatGPT не должен предполагаться имеющим сетевой доступ. При отсутствии доступа инструкция запрещает имитацию результата.

Для первого запуска надо проверить один обычный чат сотрудника на синтетическом примере. Такой end-to-end тест в данной поставке **не проводился**. Work не является частью этого решения.

Эта версия размещена в GitHub по прямому поручению владельца через подключение с доступными операциями записи. Для использования инструкции сотрудникам запись в репозиторий не нужна. Возможности конкретного подключения необходимо проверять по фактически доступным инструментам; наличие прав пользователя само по себе не создает инструмент записи.

Сохранены исходные параметры оформления. В длинных реквизитах Word может изменить переносы; побуквенное совпадение всех пробелов вне полей не гарантирует попиксельного совпадения страницы. Исходное ходатайство содержит хрупкое выравнивание пробелами в шапке. V1 не исправляет его без согласования.

Правовые абзацы взяты из пользовательских эталонов. В этой работе не выполнялась проверка действующей редакции законодательства, юридической достаточности оснований или применимости международных ссылок. Заполнение реквизитов не является заключением о готовности к судебной подаче.

## Локальная техническая проверка

```bash
python -m unittest discover -s tests -v
python scripts/fill_documents.py --data tests/synthetic_case.json --out ./out_demo
```

В `out_demo` создаются два **учебных** DOCX и внутренний `validation.json`. Не использовать учебные документы как реальные заявления. В репозиторий выходные файлы не включать.
